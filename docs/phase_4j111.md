# J111：有来源约束的 OPLS / PCFF 分型扩展

本阶段增加显式 `opls-polymer-v3` 和 `pcff-polymer-v2`；旧 profile 保持可用。**这次没有补齐全部 OPLS/PCFF 缺项。** 主要完成可由现有源库支持的分型修正，并把仍缺少可靠参数的环境保留为失败。

## 实现及来源

- PCFF：补充甲酰/甲酰胺端基的原生 `n` 类型，以及芳基氨基甲酸酯的 `n_2` / `hn2` 匹配。后者同时匹配氮和氢，避免只改氮而留下缺失的氮–氢电荷增量。
- OPLS：约束会误匹配酰胺邻位碳的通用胺规则；补充来源已定义的饱和含硫/醚环境，包括连接脂肪环的醚。保留饱和环状碳连接胺的环境，修复开发中发现的 PACM 固化产物回归。
- 使用源库中的类型、增量及键合参数；`.frc`、`.prm` 和 OPLS `.define` 均保持字节一致。改变分型仍可能改变某个原子的实际电荷与所选系数，因此不能把“数值源文件不变”理解成“所有模型的参数不变”。
- 不补零参数，不关闭电荷或缺项检查，不把其他力场的数值参数混入这些 profile。

实现与正式数值验证绑定 `3246769`；最终覆盖对照脚本见 `9e40d24`。逐来源、逐案例哈希在证据目录。

固定 982 个 DP4、氢封端输入，以及 34 个挑战输入，两个力场合计 **2,032/2,032** 完整图结果。此次没有重复测试旧 repeat 入口。PCFF 使用完整首次面板；修正环状胺规则后 OPLS 独立重测全部 1,016 项，没有只选择成功结果。

全部成功结果通过严格图/立体化学检查。这些数字是参数分配，不是 2,032 个 MD 或平衡验证。

相对历史记录，PCFF 新增 18 个成功案例，OPLS 新增 1 个。PCFF 同时有两个历史成功案例在本次失败：PI250 构象生成失败、PI1039 超时，因此总数净增 16。当前相同代码和环境下，两个案例用旧、新 profile 都失败；不能将它们认定为分型回退。PI250 在 RDKit 2026.03.6 的额外新旧 profile 对照中均成功，但该复核没有替换原始面板记录。

本轮批量覆盖及 J111 数值运行使用 RDKit **2024.09.6**；pytest、PI250 环境对照和 J112 正式配方运行使用 **2026.03.6**。历史面板的 manifest 没有显式记录 RDKit 版本。所以上表不是只改变 profile 的单变量比较。

对全部 21 个成功/失败变化案例，以当前代码、旧 profile、相同时限另行对照：19 项仍为旧失败/新成功，两个回退案例新旧皆失败。PI1113 的旧 profile 诊断为图处理失败；并非所有增益都能简单归因于一个电荷增量缺项。

另有 17 个历史成功案例的类型计数变化：当前环境下旧、新 profile 对照显示，**4 项**是甲酰端基由 n_2 转为本 profile 一致采用的 amide n 类型；另 **13 项**在当前环境下新旧 profile 的计数相同，属于相对历史的环境/图遍历差异，不能归因于本次 profile。相关芳香/杂芳香类型变化尚不能据此宣称跨 RDKit 版本数值等价。

## 数值与动力学验证

- 24 个独立 OPLS 来源 residue 的逐原子类型、电荷保持一致；3 个 PCFF 探针对照原生增量之和。
- 6 个较长独立模型通过原子置换和有限差分检查，最大力梯度误差约 **5.75×10⁻⁵ kcal/(mol·Å)**。
- 芳香聚氨酯、带甲酰端基的聚酰胺、脂肪酰胺侧链、脂肪聚砜、环状醚侧链，共 **5/5** 原生周期配方完成，每例仅 **150 fs**。
- 开发时有限差分曾超差。收紧 Ewald 精度仍未消除；关闭 LAMMPS 库仑查表后通过。报告保留这两类失败与对照，未修改生产 MD 默认查表行为，也未放宽验收阈值。
- 芳香酰胺侧链仍出现真实扭转缺项，替代的脂肪酰胺验证不代表它已获支持；亚砜和部分腈也保留负例。

早期相关回归 152 项通过；最终 profile 定向 36 项通过（含 24 个来源模型及 PACM 反应产物）。J112 另进行了跨阶段联合回归与定向复核，详见其报告。上述测试集重叠，不能相加为独立测试数量。

## 剩余不足

OPLS 面板提升仅一例，**广覆盖瓶颈仍未解决**。含 N 的整个输入成功率仍为 18/383、含 F 为 4/134、含 S 为 10/77、含 P 为 0/16；这些组相互重叠，不是单个元素的分型成功率。许多酰亚胺、含氟/磷结构，以及扭转和电荷增量环境，需要进一步核对或引入新的可信参数来源。

PCFF 尚有 62 个未成功输入，包含运行失败，不能全部视作缺参数。对原生源库缺失的项，不应通过改成不对应的泛化类型来追求成功率。下一批扩展需要按真实化学环境进行来源匹配、接点与端基检查及数值验证。

## 使用与复现

```json
{"name": "pcff", "profile": "pcff-polymer-v2"}
```

```json
{"name": "opls", "profile": "opls-polymer-v3"}
```

```bash
python -m island.forcefields.emc_profiles pcff-polymer-v2 work/pcff
python -m island.forcefields.emc_profiles opls-polymer-v3 work/opls
PYTHONPATH=.:src python scripts/benchmark_final_graphs.py \
  --pcff-field work/pcff --opls-field work/opls --out work/panel \
  --graph-only --workers 6 --timeout 180 --backend-timeout 30
PYTHONPATH=.:src python scripts/validate_j111_controls.py work/controls \
  --pcff-run work/panel --opls-run work/panel
PYTHONPATH=.:src python -m pytest tests/test_phase_4j111.py -q
```

证据见 `docs/evidence/phase_4j111/`。所有探索失败、旧 profile 对照和覆盖分母保留；复现时应明确选择并记录 RDKit 与后端版本。
